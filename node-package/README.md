# UFOBZK VPN Node — универсальный REALITY-узел

Папка для **быстрого подключения нового сервера** в качестве дополнительного
VPN-узла, управляемого с основного сайта. Узел разворачивается одной командой,
не требует домена, TLS-сертификата и nginx — работает по **REALITY** на голом
IP (для DPI выглядит как обычный HTTPS к легитимному сайту).

```
┌────────────┐   push config (HTTP, токен)   ┌─────────────────────────┐
│  Основной  │ ────────────────────────────► │  Новый сервер (узел)    │
│  сервер    │   каждые ≤5 мин               │  ┌────────┐ ┌─────────┐ │
│  (админка) │                               │  │node-api│→│  xray   │ │
└────────────┘                               │  └────────┘ │ REALITY │ │
       ▲                                     │             │  :443   │ │
       │  подписка с REALITY-ссылкой         │  ┌──────────┴─────────┘ │
       └─────────── пользователь ◄───────────┼──┘  клиент → IP:443     │
                                             └─────────────────────────┘
```

## Установка нового узла (3 минуты)

На **чистом** Ubuntu/Debian сервере под root:

```bash
git clone https://github.com/risimoDev/ufobzk.git /opt/ufobzk
cd /opt/ufobzk/node-package
bash install.sh --main-ip <IP_ОСНОВНОГО_СЕРВЕРА> --name "Finland-1" --region fi
```

Скрипт сам: поставит Docker, сгенерирует REALITY-ключи и токен, поднимет
`xray + node-api`, настроит firewall (REALITY открыт всем, node-api — только
с основного сервера) и в конце напечатает готовый блок для админки.

Опции: `--reality-port` (по умолч. 443), `--sni` (маскировка, по умолч.
`www.samsung.com`), `--api-port` (по умолч. 9090), `--token`, `--region`.
Креды дублируются в `node-credentials.txt` (chmod 600).

## Подключение к основному сайту

1. Открой `https://<твой-домен>/admin → Servers → Add`.
2. Перенеси значения из вывода install.sh (Host, API URL, API Token, Region,
   Reality Port/Public Key/Private Key/Short ID/Server Names/Dest).
3. Сохрани. Основной сервер за ≤5 минут запушит ключи пользователей —
   узел автоматически появится в их подписках как новая REALITY-локация.

> **Важно:** `Host` должен быть **IP** узла. Тогда основной сервер собирает для
> него только REALITY-инбаунд и REALITY-ссылки (без nginx/TLS), что и работает
> на голом сервере. Домен указывай только если на узле реально стоит nginx+TLS.

## Как это устроено

- **xray** (`network_mode: host`) — REALITY-инбаунд на порту хоста. Клиенты
  пустые до первого пуша; ключи приходят от основного сервера.
- **node-api** (`../xray-node`) — принимает `POST /config` с токеном, пишет
  конфиг и рестартует xray **только если конфиг изменился** (иначе соединения
  пользователей не рвутся при периодической синхронизации).
- Конфиг пушится с основного сервера (`app/remote_xray.py` →
  `_build_remote_config`), который для IP-хоста отдаёт REALITY-only.

## Управление

```bash
cd /opt/ufobzk/node-package
docker compose ps           # статус
docker compose logs -f xray # логи ядра
docker compose logs -f node-api
docker compose restart      # перезапуск
docker compose down         # остановить узел
```

## Удаление узла

1. В админке: Servers → выключить/удалить запись узла (пропадёт из подписок).
2. На узле: `docker compose down -v` и при желании `rm -rf /opt/ufobzk`.

## Диагностика

| Симптом | Что проверить |
|---|---|
| node-api не 200 | `docker compose logs node-api`; порт `--api-port` свободен |
| Узел не синхронизируется | firewall пускает `--main-ip` на api-port; токен совпадает с админкой |
| REALITY не коннектится | порт REALITY открыт (`ufw status`); SNI/ShortId/PublicKey в админке = выводу install.sh |
| xray рестартует часто | обнови репозиторий: в `xray-node/main.py` должен быть детект изменений |
